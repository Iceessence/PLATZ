# ADR-000 · Engine foundation
20 November 2026 | Selected for the first Windows development candidate. Owner acceptance pending.

## Decision
Build one native C++ application, with a C++20 portable source/API contract and MSVC 14.51 (VS 2026 18.10.3) x64. Use the stable ISO C++23 compiler mode where the qualified MSVC toolset supports it, without depending on preview features. Studio uses dynamically linked Qt Widgets 6.12.0. The Engine owns a native D3D12 device, queues, frame resources, shaders, perspective camera, depth and identification passes. Qt supplies a native child window and accessible editing controls. The renderer receives value-based render input, isolated from Qt and project storage. Hardware features are queried on the selected adapter. Explicit queues, descriptor ownership, immutable mesh sources and fences leave room for compute, parallel command recording, PBR, streaming and DXR. Implement only measured workloads. This first backend targets Windows. Other operating systems require a native surface and a separately qualified backend.

Core owns versioned SQLite .platz files, project/scene/object identities, supported built-in geometry references and material/transform source properties. On Windows use the OS-serviced SQLite library. Serialize stable source values, never widget state or GPU addresses, into project data. Keep local panel preferences separately. Typed, validated edits and undo/redo feed Studio. Project saves check the on-disk revision transactionally. Runtime projects a separate in-memory scene and consumes input independently of authoring. Begin no-code with editable named properties. Future graphs and optionally compiled code will share typed operations via a validated intermediate representation. Block native plugin and user code execution until isolation is demonstrated.

AI will consume scoped read views and stage version-bound typed proposals. Only trusted user-authorized operations may commit to Core. No model, worker or training privileges are needed to open or edit projects. First original specialist trial should use generated, rights-cleared command examples, a held-out split and deterministic baseline, with false-action and abstention measurements. Require a cancellable, resource-limited worker and independent qualification before inference can compete for editor resources.

## Alternatives and evidence
* Native C++ / Qt / direct D3D12 (selected). Single native ABI between scene, editor and renderer. Direct feature discovery, memory and barriers on the first target. Qt supplies mature docking, keyboard input and accessible controls. Costs include explicit GPU synchronization, C++ memory safety, Qt deployment/licensing, and a new backend for the next OS. Rust/wgpu offers stronger memory safety and immediate portable APIs, but native ray tracing is experimental and advanced backend escape paths still require qualification.
* Native engine with .NET 11 Studio. Attractive managed tools, UI automation and an independently replaceable engine. A second runtime and managed/native surface lifetime, input and data contracts bring extra integration risk without a demonstrated editor advantage for this slice.
* .NET 11 engine using direct low-level graphics bindings. Can own real GPU pipelines and supports strong authoring productivity. Native resource lifetime, binding lag, GC behavior in simulation and graphics interop still require explicit qualification. Installed .NET 10.0.401 does not determine this decision.

Evidence: native probe created a D3D12 feature-level 12_2 device on the local RTX 5080 and reported DXR tier 1.2. This only qualifies device availability. Require live child-window presentation, depth-correct picking after input, and isolated Play/save/reopen before expanding dependent work. Review Qt focus/high-DPI behavior, fixed-source compatibility, GPU stalls and schema changes at the next gate. Revisit the backend on serious resource/portability limitations or before production on a second OS. A separate reviewer must reproduce consequential claims. No frozen baseline yet.
